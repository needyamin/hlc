# HLC v2.0 — Production Hardening: Docker Removal + Broad Language Support + Suitability Analysis

## Context

HLC (Heavy Load Checker) is a stdlib-only Python HTTP load tester with a web UI, SLO grading (S1–S9), a cross-language runtime benchmark (currently 5 toolchains: Spid3r, PHP, Python, Node, Rust), and deep Docker instrumentation. The goal: make it robust, accurate, and production-ready with **broad language support** (Python, Java, JS, TS, C, C++, C#, Go, Rust, PHP, Ruby, Kotlin, Swift…), **heavy-load testing**, **scalability analysis**, and **technology suitability assessments** — with strict measured-vs-estimated integrity — and **remove Docker for now** (code deleted from the working tree; restorable from git history when needed). Archived docker-era runs keep rendering/migrating via the untouched v1→v2 schema migration.

---

## 1. Remove Docker (working tree)

**Delete:** `heavyload/docker_probe.py`, `heavyload/collectors/cgroup.py`, `heavyload/collectors/docker_stats.py`, `heavyload/collectors/mysql.py`, `scripts/lab_up.py`, `scripts/lab_down.py`.

**Simplify (all Docker branches removed, Windows-only behavior kept):**
- `heavyload/config.py`: `RUNTIME_ENVIRONMENTS=("windows",)`; drop docker presets, `container`/`mysql_container`/`cpuset_*`/`runtime_comparison.{container,include_container}` defaults; `normalize()` maps a legacy `"docker"` value → `"windows"` with a logged warning and strips legacy keys (archived-run compatibility); drop `apply_runtime_environment`'s docker branch.
- `heavyload/samplers.py`: remove cgroup/docker-stats/mysql streams + `kill_orphans`; keep health probe; **add a generator self-sampler** (own-process CPU via `time.process_time()`, working set via ctypes `GetProcessMemoryInfo` / `/proc/self/status`) → `series.generator_series` (measured client-side utilization).
- `heavyload/engine.py`: drop `container`/`mysql_container` params, `inspect_before/after`, `mysql_series`; series = `health_series`, `proc_series`, `generator_series`; reword disclosures/notes.
- `heavyload/runner.py`: preflight drops daemon/cgroup rows; `environment_info` drops docker fields; drop the Windows-forcing block (single mode now).
- `heavyload/runtime_comparison.py`: remove `resolve_container()`, container probe, docker variants, `_cleanup_container()`.
- `heavyload/grading.py`: keep S5/S6/S8 logic intact (archived-run re-grading + selftest synthetic path) — new runs simply always hit the honest N/A path with a client-only explanation.
- `heavyload/schema/*`: untouched (docker_lab remains a valid *historical* mode label; `fingerprint.docker_version` stays, always `""`).
- `cli.py`: remove `--runtime-env/--container/--mysql-container/--mode/--benchmark-mode` docker flags.
- `server.py`: remove `dp` import, `/api/containers`, docker keys from bootstrap.
- `ui/`: remove runtime radio cards, container selects, docker pill, "(Docker only)" hints.
- `heavyload/targetspec.py` + `targets/_schema.json`: make `image` optional (no longer required validation); drop `docker_run_args()`.

## 2. Broad language support — runtime comparison

New package `heavyload/comparison_sources/` (one module per language keeps the 1,821-line file manageable): `spid3r.py`, `python.py`, `javascript.py`, `php.py`, `rust.py` (moved), plus **new: `java.py`, `typescript.py`, `c_lang.py`, `cpp.py`, `csharp.py`, `go.py`, `ruby.py`, `kotlin.py`, `swift.py`**. Each exports per-workload sources matching the pinned checksums (`runtime_comparison.py:79-85`).

Wire-up at the 4 existing seams: `detect_tools()` (runtime_comparison.py:914 — add probes: `java`, `javac`, `kotlinc`, `gcc`/`clang`, `g++`/`clang++`, `dotnet`, `go`, `ruby`, `swiftc`, `tsc`), `_build_artifacts()` (:955 — javac, kotlinc→jar, gcc/g++ `-O2`, dotnet csproj+`dotnet build -c Release`, `go build`, swiftc, tsc→node; separate longer `build_timeout_s` for kotlinc/dotnet), `_variants()` (:992 — new variants), `summarize_data()` (:1331 — generalize baselines: keep `vs_php`/`vs_python`, add `vs_fastest` + a full pairwise geomean ratio matrix).

Windows specifics: resolve `.bat`/`.cmd` toolchains (`kotlinc.bat`, `tsc.cmd`) via `shutil.which` + `cmd /c` wrapper in `_call()`. Workload B (JSON) coverage is per-language native serializer: py/js/ts/php/ruby/go/csharp/swift yes; **java/kotlin/c/c++/rust skipped with a documented reason** (no stdlib JSON — honest "not applicable", never simulated). Integer semantics pinned to i64 wrap to match existing checksums.

New CLI: `python cli.py --verify-sources` — compiles+runs every detected toolchain against the pinned checksums and prints a verification table (also run during implementation for every toolchain installed on this machine; absent toolchains auto-skip).

## 3. Measured per-variant CPU/memory — new `heavyload/procmetrics.py`

Cross-platform stdlib child-process metrics: Windows = ctypes `OpenProcess`+`GetProcessTimes`+`GetProcessMemoryInfo` (peak working set); POSIX = `os.wait4` rusage / `VmHWM` poll. `runtime_comparison` rows gain `peak_rss_bytes`, `cpu_user_s`, `cpu_kernel_s` (None → "unavailable", never fabricated). Feeds suitability analysis with real memory/CPU data.

## 4. Heavy-load profiles

`heavyload/config.py` `PRESETS`: add **`heavy`** (ramp 25→50→100→150, sustained C=150 60s, spike 175/200, soak 50) and **`stress`** (ramp to 300, long sustained + soak, spike to max_concurrency 400). Guardrails/SLOs unchanged; profiles flow to UI via existing `presets_payload`.

## 5. Scalability analysis — new `heavyload/scalability.py`

Extend `engine._run_phase()` (engine.py:284) to record per-step windows (C, start/end) → aggregate from `raw.jsonl`: rps, p50/p95/p99, error% per concurrency level. Output `results["scalability"]`: throughput-vs-C curve, efficiency (rps/C), **knee-point detection** (last C before marginal-gain collapse / p95 doubling), scaling classification (linear/sublinear/plateau/degraded) — all measured, with evidence counts. Rendered as a new report section with 2 SVG charts + step table.

## 6. Technology suitability — new `heavyload/suitability.py`

Transparent weighted scoring per language. **Measured criteria** (from runtime comparison + optional campaigns): compute performance (geomean ratio vs fastest), memory efficiency (peak RSS), CPU efficiency, and HTTP throughput/latency/stability when campaign data exists. **Documented criteria** (clearly labelled, never passed off as measurements): ecosystem maturity, maintainability, reliability track record, concurrency model, ecosystem/library depth — a curated knowledge base with per-criterion 0–10 scores + one-line justifications. Config block `suitability: {weights…}`; output `suitability.json` + standalone `suitability.html` + a ranking section in the main report; every row shows provenance (`measured`/`documented`) and the measured-vs-documented contribution split; framework-level comparison included as a documented-only table.

## 7. Data integrity & anomaly detection — new `heavyload/quality.py`

Checks wired into `run_benchmark` → `results["quality"]` and surfaced as grading findings: timeline sampling gaps, percentile monotonicity, runt phases (requests below expected floor), malformed `raw.jsonl` line count, campaign repeat-CV noise flags, checksum-gate rejections — each with status + plain-language detail.

## 8. Report overhaul (`heavyload/report.py`)

`build()` (:325) gains sections: **Methodology & evaluation criteria** (phases, workload, fairness, timing method, vantage), **Scalability & concurrency analysis**, **Load-generator utilization** (charts + KPIs), **Data quality & accuracy considerations** (checks, sampling granularity, error sources, measured-vs-estimated disclosure), **Strengths / weaknesses / limitations** (each bullet cites a measured metric), **Technology suitability ranking** (provenance column). Section numbering + selftest assertions updated; report stays single-file inline-SVG/no-JS.

## 9. Comparability policy — single-host client-side comparisons

Without Docker, cross-language HTTP comparison needs client-only runs to be rankable when they're genuinely equivalent: extend `schema.can_compare()` (metrics.py:160) to allow pairs where both runs are `client_only` **and** loopback targets **and** equal `schema_version`/`workload_class`/new `fingerprint.generator_fingerprint` (host+platform+CPU); add `visibility: "client_only_same_host"` assigned by the runner for loopback targets. External-host client-only runs stay refused. Comparison reports gain explicit "single-host client-side — not a server-resource benchmark" caveats. Archived docker_lab runs still compare only with each other (unchanged).
