The plan — six phases, each gated by a re-measurement

Sequenced by leverage per week of work. Phases 0→3 are the ranking movers; 4–6 consolidate. Check off each task — progress autosaves.

Phase 0 — Integrity & measurement hygiene do first, ~1 day0/4

Why: the prime-counting fingerprint (src/vm/mod.rs:1886-2036) is a benchmark-shaped pattern hardcoded into the VM. For a scientific submission this must go, and it can only be removed safely once general superinstructions exist (Phase 3). Also: median-of-3 with a 1 ms now_ms() timer produces "identical 8.0 ms" readings — raise repeats so improvements are statistically visible.

Phase 1 — Unbox list-of-lists rows (fixes workload E) highest leverage, ~1–2 weeks0/5

Evidence: matmul native = 85 ms because analyze_unboxed_lists (src/native/ir.rs:2693) rejects rows — ir.rs:2730 requires empty type args (so list<list<int>> never qualifies) and ir.rs:2739-2748 only accepts literals/list() calls, not let ai = a[i]. Result: ~8.5M extern calls through spid3r_index_get (rt.rs:2207-2278) + spid3r_binop (rt.rs:1210-1322), each with a mutex try_lock and tag match.

Expected impact (projection): E: 85 ms → ~6–10 ms (Node parity or better). Geomean native: 10.55 → ~7 ms. Compute score 0.29 → ~3. CPU 0.0 → ~2–3.

Phase 2 — Make the runtime inline-able (cross-LTO) ~1 week, helps every workload0/4

Evidence: generated code calls prebuilt helpers (spid3r_index_get, spid3r_binop, spid3r_list_push, …) from libspid3r_lang.a, linked after compilation with no cross-module LTO — so no hot helper can ever inline into generated loops (src/native/mod.rs:136-204). The repo already fixed this disease once for binops (ir.rs:4667-4683); the same fix one layer up is pending.

Phase 3 — Real VM superinstructions + dispatch prelude trim ~2–3 weeks0/6

Evidence: tree/VM/bytecode all sit at 8 ms on prime while native hits 1 ms. Dispatch pays ~8–10 fixed ops per instruction (src/vm/mod.rs:1277-1380); fusion is runtime byte-peeking over ~1,100 lines (vm/mod.rs:1426-2543) including the benchmark-shaped prime fingerprint (:1886-2036); opt.rs has folding/branch/rotation but no superinstructions, no inlining, no type specialization.

Expected impact (projection): prime 8 → 2.5–4 ms (general, not fingerprinted); map 7 → 3.5–4.5 ms; text 27 → 12–15 ms; interpreted matmul 168 → 110–130 ms (full fix is Phase 5).

Phase 4 — JSON: arena parse + global key interning ~1–2 weeks0/4

Evidence: JSON algorithms are already good (thread-local byte writer stdlib/mod.rs:3111-3178; byte-oriented parser with key interning mod.rs:3194-3216). The cost is the boxed value model: every parsed node is Arc<Mutex<MapData>> re-boxed through alloc_heap_v2 (rt.rs:260-276) — hundreds of thousands of box+lock events vs V8's inline-property objects.

Expected impact (projection): B: native 64 → 30–40 ms (beats PHP 71.5, approaches Python 57.4; Node's 17.9 needs Phase 5).

Phase 5 — Type-specialized bytecode (the durable answer) optional, ~4+ weeks0/3

Why: the structural ceiling for the interpreted engines is the 35–45-variant Value enum in every slot (src/value/mod.rs:679-750). The semantic pass already computes type info; nothing consumes it in the VM. interpreter/fast.rs:728-750 already proves unboxed i64 evaluation at AST level.

Phase 6 — The non-compute criteria (getting to #1, honestly) ongoing0/3

Integrity rule that cuts both ways: the harness refuses to invent documented scores. The ranking climbs on measured evidence — which is precisely what makes a #1 rank meaningful in journal review.

Verification loop — how every phase is proven

  • Correctness first: every HLC run checksum-gates each variant (RESULT 5133 121013308 / 249868800 9163 / 44432313 100000 / 1295428 300465975 / -1985 -40) — a wrong result is rejected, never timed.
  • Before/after in one artifact: python cli.py --runtime-comparison --runtime-repeats 7 writes comparison + suitability into ONE report.html with numbered figures; run it before and after each phase and attach both to the phase PR.
  • Spot checks: --workloads matmul (Phase 1), --workloads prime (Phase 3), --workloads json (Phase 4).
  • Full-suite regression: python selftest.py + python -m unittest discover -s tests stay green.
  • Journal evidence pack: the Abstract + Fig. captions + head-to-head heatmap in report.html are the reviewer-facing artifacts; runtime_comparison.json (every repeat, every checksum) is the data-availability statement.

What NOT to do

  • Don't add more benchmark-shaped fingerprints. General superinstructions give the same speed honestly; the checksum gate already prevents wrong-result "optimizations".
  • Don't trade memory for speed carelessly. Memory efficiency (6.8/10) is Spid3r's best measured criterion.
  • Don't weaken overflow semantics. The checked-int behavior is byte-identical across engines and near-free — the cost was the extern-call shape, not the check.
  • Don't optimize the harness around Spid3r. The scoring model is what makes a future #1 rank credible.
