Two read paths, one network boundary. An external HTTP client can never see server CPU, RAM or OOM events.

Developer notes - 01 - System context

  • heavyload/http_client.py owns make_connection() and one-shot probe(); the load generator never uses anything else to reach the target.
  • docker_probe.py provides list_containers(), resolve_container(), cgroup_caps() and docker_available() - all via the Docker CLI, no SDK.
  • collectors/cgroup.py runs ONE Python process inside the container and reads memory.stat anon, memory.current, memory.peak, cpu.stat, io.stat, *.pressure and pids.current with plain open().
  • If the container has no python3, samplers.py falls back to collector_mode=legacy_shell (forks grep/awk/sleep); idle CPU can read 8-15% instead of ~0.85%. Always check environment.fingerprint.collector_mode.
  • On Windows the cgroup files live in the WSL2 VM: reachable only via docker exec. Target, VM and load generator share physical cores.

Three entry points, one runner, pluggable collectors, one result document. Dashed boxes are optional.

Developer notes - 02 - Module architecture

  • runner.run_benchmark(cfg, root, log, preflight_result, bench_holder) is the SINGLE orchestrator - cli.py and server.py /api/run/start both call it, so a feature added there works in both UIs.
  • engine.Benchmark.run() returns the results{} dict; grading.grade() adds adjudication, schema.ensure_current() adds v2 identity fields.
  • runtime_comparison.run() is wrapped in try/except: any exception becomes status=error + a warning in results.json, never a lost run.
  • report.build() emits one self-contained HTML (inline SVG charts, no JS); paths.SAFE_ARTIFACTS is the whitelist used by server.py for /runs/<run-id>/<artifact>.
  • UI liveness: server.py reads status.json; ui/app.js polls /api/status and /api/log at 1 Hz. No WebSockets, no framework.

Eight orchestration steps and the eight HTTP phases. The language comparison deliberately runs last.

Developer notes - 03 - One run, start to finish

  • config.preset_phases(name) returns the 8 phases; profiles only change durations (smoke ~33 s, quick ~3.5 min, standard ~24 min).
  • engine._run_phase() drives one phase, _worker() issues requests, _writer() appends one JSON line per request to raw.jsonl, _guard_check() can set _set_abort(reason).
  • Guardrails come from config.guardrails: max_anon_mib, min_host_free_gb, max_error_rate_pct, max_consecutive_failures. On abort, cooldown_s + reprobe_s still run and partial results are written.
  • Step 7 sits after ensure_current() on purpose - the HTTP result is already aggregated and graded before a single language program is spawned.

Every published number traces back to a raw line, a cgroup sample or a verified timing.

Developer notes - 04 - Data flow: raw bytes to verdict

  • engine._aggregate_requests() -> metrics.http (see schema/metrics.py empty_http()); _aggregate_samples() -> metrics.resources (empty_resources()). Latency keys: p50/p90/p95/p99/max/mean.
  • grading.grade() registers S1-S9, findings, health_score (0-100) and a GO / NO-GO / INSUFFICIENT verdict.
  • schema/migrate.py performs an ADDITIVE v1 -> v2 migration: no v1 key is deleted, renamed or coerced, so archived reports still render.
  • Writes go through util.atomic_json(); report.py draws inline SVG charts from the same dict - no second data source, no estimates.

Only runs measured from the same vantage point may be ranked.

Developer notes - 05 - Modes and the comparability gate

  • schema/metrics.py:can_compare(a, b) requires equal benchmark_mode, visibility, schema_version and workload_class, then rejects any run whose visibility == "client_only".
  • VISIBILITY_LEVELS = ("full_server", "client_only", "server_via_adapter"); benchmark_mode=auto picks docker_lab when resolve_container() finds a container.
  • compare.py sets comparable=False + a reason and still returns raw rows; report_compare.py prints NOT COMPARABLE instead of a leaderboard.
  • instrumented_live is a declared seam, not an implementation: add a collectors/base.Collector subclass for your Prometheus / APM endpoint.

Pinned workloads, real variants, one checksum gate, no simulated numbers.

Developer notes - 06 - Language runtime comparison

  • runtime_comparison.py: pinned PRIME_N, JSON_ROWS/ROUNDS, MAP_KEYS/ROUNDS and the EXPECTED checksum dict. Change a constant and you MUST recompute EXPECTED or every variant is rejected.
  • Each generated program prints exactly two lines: RESULT <a> <b> and TIME_US <n>; _parse_output() enforces that contract.
  • _variants() builds tree-walk, VM, VM --no-opt, .matrixc exec, build --release, rustc -O, Node, PHP, Python AND the real binary copied into the container with docker cp.
  • detect_tools() probes toolchains; missing ones are skipped with a warning. _cleanup_container() removes /tmp/hlc_rt_* afterwards.
  • Spid3r has only now_ms() (1 ms resolution), so workloads are sized well above 28 ms. Its JSON builtin is json_write / json_parse, NOT json_encode.

Invariants & gotchas

Rules that are easy to break and expensive to debug. Treat these as the project's contract.

  1. Stdlib only - No pip install for the core. Optional extras (psutil, Playwright) are never required; the CDP client uses plain socket.
  2. No collector fails a run - Missing Docker, missing in-container python3, missing runtime endpoint and missing Chrome all degrade to unavailable labels.
  3. Additive schema - v1 keys are never deleted, renamed or coerced - archived reports keep rendering.
  4. Visibility is explicit - can_compare() refuses to rank a client_only run against a docker_lab run. The tool would rather say NOT COMPARABLE than print a wrong winner.
  5. Instrumentation must not perturb - One in-container Python process, no shell forks, deterministic stdin shutdown. Treat collector_mode=legacy_shell CPU numbers as inflated.
  6. No simulated numbers - Workload constants are pinned; a variant with a wrong checksum is REJECTED, never published; missing toolchains are skipped with a warning.
  7. Compute speed is not HTTP throughput - The language comparison measures in-process milliseconds; RPS / p99 come from the HTTP load test. Never compare the two.
  8. Comparison is failure-safe - It runs AFTER the HTTP schedule; an exception becomes a warning in results.json and the load result survives.
  9. Git Bash / MSYS path trap - Leading / args and docker cp ...:/tmp/x get rewritten to Windows paths. Set MSYS_NO_PATHCONV=1 and MSYS2_ARG_CONV_EXCL='*' in subprocess env.
  10. Shared cores on Windows - Pin the target (--cpuset-cpus) and the generator (fairness.cpuset_generator), subtract the idle baseline, and keep host_shared_cpu=true. Never quote raw lab CPU% as absolute capacity.
  11. Spid3r specifics - Only now_ms() (1 ms resolution); JSON builtin is json_write, not json_encode. The deployed store still runs the tree-walk engine, the slowest of the measured variants.
